## Preuve de livraison obligatoire avant facture (lot POD, PR 1 serveur)

**Quoi** : table `mission_pod_files` (ajouts seulement), routes `POST|GET /api/missions/:id/pod-files` et `GET /api/missions/:id/pod-files/:fileId`, événement `mission_pod_uploaded`, détection du type réel par signature (`server/lib/file-signature.ts`), garde 409 dans `generateInvoiceFromMission` (mission livrée ou clôturée, au moins un fichier POD), et `podUrl` / `podUploadedAt` retirés de `insertMissionSchema`. Conséquence : les missions livrées non encore facturées ne peuvent plus l'être sans POD ; la logistique dépose le POD puis facture.
**Comment** : test de contrat rouge d'abord sur la faille (POST avec `podUrl` écrit la colonne), puis correctif ; routeur monté avant celui des missions ; contrats existants qui facturent (`client-invoice-generate`, `mission-price-edit`) adaptés avec une mission livrée et un POD posé par `tests/support/pod.ts`. Les e2e 13, 17 et demo/04 passent par la PR 2.
**Pourquoi** : sans preuve de livraison, une facture pouvait partir sur une mission non livrée ; le champ de preuve était lui-même écrivable par le corps d'une création de mission (voir LESSONS_LEARNED, 2026-11-10).
**Preuve** : `node node_modules/vitest/vitest.mjs run --config vitest.contract.config.ts tests/contract/mission-pod.contract.test.ts tests/contract/client-invoice-generate.contract.test.ts tests/contract/mission-price-edit.contract.test.ts` (base locale dédiée) ; `tsc --noEmit` à 0 `error TS`.
