## Pleins validés immuables : réserves de relecture de 0a (PR #630)

**Quoi** : (1) groupe de satellites `treasury` (`/api/treasury`) ajouté à `fuel_record_changed`, repris par la boîte d'annulation via `satelliteTargetsOf` ; (2) `POST /api/fuel-records/:id/cancel` entre dans la table des écritures de véhicule retiré (lookup `fuelRecord`), `TABLE_FLOOR` 47, contrat 409 ajouté ; (3) message du budget soldé : « Le budget de la mission est soldé : l'annulation n'est plus possible, contactez la comptabilité. » ; (4) `isMissionBudgetSettled` déplacée dans `shared/contracts/mission-budgets.ts`, utilisée par le solde, les dépenses, l'écran et le service des pleins ; (5) AGENTS.md : motif de 3 à 500 caractères ; (6) entrée LESSONS_LEARNED sur l'interblocage.
**Comment** : la garde est pilotée par la table `RETIRED_VEHICLE_WRITE_ROUTES` (middleware), aucune garde à écrire dans la route. Les chemins de `mission-budgets-service.ts` ont tous l'ordre mission puis budget.
**Pourquoi** : sans la trésorerie, `/api/treasury/accounts` gardait l'ancien solde jusqu'à 5 minutes ; annuler un plein d'un véhicule retiré contournait la règle L3 ; « rouvrez le budget » n'a aucun chemin.
